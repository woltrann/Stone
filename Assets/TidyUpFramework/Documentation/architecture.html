Core Architecture

How the framework is put together, why it is split this way, and where to plug in your own code.

The four core prefabs

Everything a playable level needs comes from four prefabs in TidyUpFramework/Prefabs. GameObject > Tidy Up Framework > Complete Level Setup drops the first three into an open scene and adds an EventSystem when none exists.

PrefabContainsTypical changes
TidyPlayerFirst person controller, camera, interactor, placement preview, cleaning interactor, camera feedbackMove speed, reach distance, interaction layers, head bob
TidyLevelSystemsLevel manager, score and combo, hints, feedback, tutorial runner, target highlighterAssign your Level Definition to the Level Manager; swap feedback profiles
TidyHUDHUD, objective list, pause, settings, controls, results screen, mobile touch controlsColours, fonts, layout, which panels are shown
TidyMainMenuMain menu, level select, settings, controls, creditsTitle, background scene, Level Catalog

Edit the prefab assets themselves for project-wide changes, or override a placed instance for changes that apply to one scene only. Every scene and level is data: the prefabs never need code changes to run a new level.

Design principles

PrincipleWhat it means in practice
Data firstAnything a designer tunes lives in a ScriptableObject: objects, categories, tags, rules, objectives, levels, scoring, combos, hints, feedback, tutorials, audio cues.
Small componentsEach MonoBehaviour does one job. A shelf is a TidyRowZone; a bin is a TidyContainer; nothing knows about "books".
Events over referencesSystems react to events (ObjectPlaced, ProgressChanged, ComboChanged) instead of polling each other.
IDs for scene linksAssets refer to scene objects by string id (TargetId, InstanceId), so data assets never hold scene references.
Replaceable servicesInput, highlighting, audio, saving and progress are interfaces registered in TidyServices. Swap any of them without touching gameplay code.

Services and lifetime

TidyFramework.Initialize() runs automatically before the first scene loads. It reads Resources/TidyUpFrameworkSettings and creates the persistent services on a hidden [Tidy Up Runtime] object:

ServiceLifetimePurpose
TidySaveService (implements ITidyProgressService)ApplicationProgress, stars, best scores/times, tutorial completion, settings persistence
TidySettingsServiceApplicationApplies graphics, audio, input and gameplay settings; re-applies after each scene load
TidyAudioService (ITidyAudioService)ApplicationPooled sound effects, music and ambience cross-fades, channel volumes
TidySceneLoaderApplicationFade transitions and level loading
TidyLevelManager, TidyInteractor, TidyInputReader, TidyHintSystem...SceneRegistered in TidyServices while enabled
if (TidyServices.TryGet(out TidyLevelManager level))
{
    level.ProgressChanged += progress => Debug.Log("Tidy: " + progress);
}

Registries

TidyObjectRegistry and TidyTargetRegistry keep every object and placement target in the loaded scenes, with fast collider look-ups used by aiming. They also relay global events, so a system that cares about every placement subscribes once:

TidyTargetRegistry.AnyObjectPlaced += placement =>
{
    if (placement.IsCorrect)
    {
        Debug.Log(placement.Object.DisplayName + " placed in " + placement.Target.DisplayName);
    }
};
